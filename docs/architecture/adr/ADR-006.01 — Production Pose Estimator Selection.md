## Context

ADR-006 required a Milestone 0 measurement-based comparison of the MediaPipe facial-transformation-matrix estimator and the calibrated interocular-scale estimator. The approved and frozen authority for that comparison is Pose Estimator Experiment Specification Draft v0.4, experiment procedure version 3, evidence schema version 1, and validator version 1, recorded by `ORC-POSE-ESTIMATOR-001`.

The claim-bearing M0D7 run is `run-1790638307359`, experiment run `m0d7-20260928232502757`. Its validated source ZIP has SHA-256 `872A833671004173F40A966B68095D65911252F1261EE902A84434267BB48EDE` and is preserved at:

`evidence/m0d/estimator-experiment-v3/run-1790638307359/`

The validator passed all 21 checks with zero failures, warnings, procedural invalidations, or anomalies. The run used the verified 640 × 360 at 24 FPS camera configuration, recorded zero dropped frames, 75 calibration observations, 6,101 evaluation observations, 6,093 face-detected observations, 93 procedure steps, and 186 paired start/end markers. Both candidates replayed from the same authoritative trace.

The evidence manifest records application build `add62305be364912f735bf3ad7171a2a3e2bf71c`. The later UI-clarification commit `a006652569d2e8e3d2b19f87b77fdacf9c405fca` changed only operator movement wording, Ready-phase wording, and deterministic instruction regression tests. It did not change targets, timing, cycles, estimator implementations, capture behavior, evidence schema, replay, metrics, validator behavior, or oracle semantics. This is an accepted provenance caveat, not an evidence invalidation; the evidence independently establishes that the repeated Y movement was physically performed correctly.

## Decision

Select Estimator A, `mediapipe-facial-transform-v1` version `v1`, as the production estimator for the M0D → M0E handoff.

Estimator-intrinsic calibration from the accepted evidence is:

- `scaleA = 1.259167661839453`
- `zMedianRaw = 476.5052488113386`
- `ZrefCameraMm = 600`
- camera origin `{ x: 0, y: 103.188, z: 0 }` mm
- configuration hash `fnv1a64-825a99daebb20f6c`
- MediaPipe package `@mediapipe/tasks-vision@1.0.1`

The canonical face-model provenance remains owned by the frozen experiment specification and its pinned task/model artifacts; this ADR does not duplicate those constants. The estimator identity and configuration are the host-private values to be handed to M0E.

Neither candidate had a frozen hard structural failure. Both passed the frozen X/Y/Z structural ordering checks, produced approximately 15.63 Hz valid-pose cadence, and produced valid output for all face-detected observations. Estimator B had some static repeatability and absolute-scale advantages, but Estimator A had materially better Z stability, continuity, natural-motion behavior, and especially partial-head-turn robustness. The observed partial-head-turn Z range was approximately 18.4 mm for A versus approximately 191.9 mm for B. Overall discontinuity was approximately median 1.68 mm, p95 19.29 mm, and maximum 51.87 mm for A, versus approximately 95.91 mm maximum for B.

A’s remaining principal errors appear compatible with the approved downstream independent per-axis scale and offset calibration model. B’s yaw-correlated depth behavior is pose-dependent and is not correctable by ordinary independent per-axis scale and offset. No solvePnP/OpenCV escalation is required by this decision; it remains deferred.

## Consequences and limitations

- M0E may measure and apply the approved downstream independent per-axis scale and offset, followed by the approved pose filtering path.
- A has significant raw scale/bias before M0E calibration; this decision does not claim final calibrated/filtered NFR compliance.
- A’s far-depth repeatability is weaker than neutral, and repositioning can create transient jitter.
- Useful pose cadence is approximately 15.63 Hz: above the experiment minimum but below the preferred 20–30 Hz range.
- Physical target placement is manually measured.
- M0D selection does not prove final filtered/calibrated NFR compliance.
- M0E must not reinterpret MediaPipe matrix layout, change canonical landmarks or estimator equations, add orientation-conditioned/nonlinear correction, replace the selected estimator, or introduce solvePnP/OpenCV without the appropriate new architecture review.

The frozen experiment, oracle semantics, estimator formulas, metrics, structural criteria, procedure, targets/timing, invalidation rules, interpretation rules, Class C status, and change authority remain unchanged.
